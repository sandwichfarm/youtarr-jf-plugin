## Manifest schema

The repo-root `manifest.json` is a top-level JSON array; one entry per plugin, each with a
`versions` array (jprm-generated schema, sourceUrl rewritten to the Release asset):

```json
[
  {
    "guid": "80302d7f-7fc3-4b1c-9a3f-fd85b98b9a69",
    "name": "YoutarrMetadata",
    "owner": "sandwichfarm",
    "category": "Metadata",
    "overview": "...",
    "description": "...",
    "versions": [
      {
        "version": "1.0.0.0",
        "targetAbi": "10.10.0.0",
        "sourceUrl": "https://github.com/sandwichfarm/youtarr-jf-plugin/releases/download/v1.0.0.0/youtarrmetadata_1.0.0.0.zip",
        "checksum": "0f070c77e2d1b1599585dbb1d4749979",
        "changelog": "...",
        "timestamp": "2026-06-09T22:50:19Z"
      }
    ]
  }
]
```

- **sourceUrl:** `https://github.com/sandwichfarm/youtarr-jf-plugin/releases/download/v1.0.0.0/youtarrmetadata_1.0.0.0.zip`
  (jprm names the ZIP lowercase `youtarrmetadata_<version>.zip`; the tag is `v<version>`).
- **checksum:** MD5 of `dist/youtarrmetadata_1.0.0.0.zip`, computed by jprm at build time —
  verified equal to `md5sum`/`hashlib` of the produced ZIP. Never edit the ZIP after build;
  re-run `package.sh` to regenerate both the ZIP and the manifest.
- The script preserves jprm's `checksum`, `targetAbi`, `timestamp`, `changelog`, `guid`, and
  `name`; only `sourceUrl` is (re-)asserted to the resolvable release URL.

### How `package.sh` derives the URL
Precedence: `REPO_URL` env var (used by CI) → `git remote get-url origin` (normalizes
`git@github.com:OWNER/REPO.git`, `ssh://…`, and `https://…(.git)` all to
`https://github.com/OWNER/REPO`) → default `https://github.com/sandwichfarm/youtarr-jf-plugin`.
Then `sourceUrl="${REPO_URL}/releases/download/v${VERSION}/youtarrmetadata_${VERSION}.zip"`.
Idempotent (`set -euo pipefail`); a second consecutive run exits 0 (`jprm repo add` updates the
GUID entry in place rather than duplicating it).

## How a user installs

**Repository catalog (preferred — what this task enables):**
In Jellyfin: Dashboard → Plugins → Repositories → Add, and paste the raw manifest URL:
`https://raw.githubusercontent.com/sandwichfarm/youtarr-jf-plugin/master/manifest.json`.
The plugin appears in the catalog; installing it downloads the ZIP from the manifest's
`sourceUrl` (the Release asset) and verifies the MD5 checksum.

**Manual ZIP-drop (fallback — unchanged):**
Download `youtarrmetadata_1.0.0.0.zip` from the GitHub Release, extract it into
`$JELLYFIN_DATA/plugins/YoutarrMetadata_1.0.0.0/`, and restart Jellyfin.

## Workflow design (`.github/workflows/release.yml`)

- **Triggers:** `push` tags matching `v*.*.*`, plus `workflow_dispatch`.
- **Permissions:** `contents: write` only — no secrets beyond the built-in `GITHUB_TOKEN`.
- **Steps (pinned action versions):**
  1. `actions/checkout@v4` — full history (`fetch-depth: 0`), token persisted for push-back.
  2. `actions/setup-dotnet@v4` with `dotnet-version: 8.0.x`.
  3. Install jprm via `pip install --user jprm`, then add `~/.local/bin` to `GITHUB_PATH`.
  4. `bash scripts/package.sh` with `REPO_URL=${{ github.server_url }}/${{ github.repository }}`
     so the manifest sourceUrl matches the release being created.
  5. `softprops/action-gh-release@v2` — creates the Release for the tag and uploads
     `dist/youtarrmetadata_*.zip` (`fail_on_unmatched_files: true`).
  6. Commit the refreshed `manifest.json` back to the default branch: checks out the default
     branch (the tag build is detached HEAD), stages `manifest.json`, and **guards with
     `git diff --cached --quiet`** so an unchanged manifest is a clean no-op (`exit 0`) and
     never fails the job; otherwise commits `chore(release): update manifest for <tag>` and pushes.
- **Release-cutting flow:** bump `version:`/`changelog:` in `build.yaml`, then
  `git tag v1.0.0.0 && git push --tags`.
