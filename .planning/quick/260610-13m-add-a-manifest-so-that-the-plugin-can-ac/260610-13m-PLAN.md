# Quick Task 260610-13m: Make the plugin installable via a Jellyfin plugin repository

## Problem

Phase 4 produces `dist/manifest.json`, but it is git-ignored, has a placeholder `sourceUrl`, and nothing hosts the ZIP — so the Jellyfin "Add repository" install flow cannot work. Manual ZIP-drop already works; this task makes the *repository* install path real.

The real GitHub repo is `github.com/sandwichfarm/youtarr-jf-plugin` (from `git remote origin`). Use that everywhere — no placeholders.

The root manifest must keep the jprm-computed MD5 `checksum`, `targetAbi`, `timestamp`, `changelog`, guid, and name — only `sourceUrl` is rewritten to the resolvable release URL. Keep the script idempotent (`set -euo pipefail`), and print the written manifest path + sourceUrl at the end.
4. Run `bash scripts/package.sh` and confirm it writes a tracked repo-root `manifest.json`.

<action>

Steps: checkout (full history, with token allowing push to the default branch); set up .NET 8 (`actions/setup-dotnet@v4`, `dotnet-version: 8.0.x`); install jprm (`pipx install jprm` or `pip install --user jprm`, ensure it is on PATH); run `scripts/package.sh` with `REPO_URL=${{ github.server_url }}/${{ github.repository }}` so the manifest sourceUrl matches the release being created; create a GitHub Release for the tag and upload `dist/youtarrmetadata_*.zip` as an asset (use `softprops/action-gh-release@v2` or `gh release create "$GITHUB_REF_NAME" dist/youtarrmetadata_*.zip`); then commit the regenerated repo-root `manifest.json` back to the default branch (`git config user`, `git add manifest.json`, commit `chore(release): update manifest for ${tag}`, push) — guarded so it is a no-op when manifest.json is unchanged, and never fails the job on "nothing to commit". Add a top-of-file comment documenting: tag with `git tag v1.0.0.0 && git push --tags`, and that users install by adding `https://raw.githubusercontent.com/sandwichfarm/youtarr-jf-plugin/<default-branch>/manifest.json` as a Jellyfin plugin repository.
